## Why

`CalendarPage` is still exactly what it was at the initial mockup port: a hardcoded 3-week grid for a fixed "September 2026", decorative prev/next arrows, a hardcoded selected/today pair, and a coupon list built from two `code ===` string checks against `mockPromoCodes` — untouched since Codes moved to real, database-backed coupons and user-managed channels. It's currently unusable as an actual calendar (it always shows the same fake month) and doesn't reflect any coupon a user has actually created. This proposal makes Calendar a real, navigable month view over live data, matching the interaction the maker sketched from the mockup: navigate months, jump to any month/year, tap a day to see what's active on it, and reuse the same coupon card/detail popup Codes already has.

## What Changes

- Replace the hardcoded 3-week `days` array and fixed "September 2026" label with a real, computed month grid (leading/trailing days from adjacent months dimmed, correct weekday alignment, real leap-year-safe day counts) driven by a `visibleMonth` (year + month) state.
- Make the `‹`/`›` header buttons functional: each moves `visibleMonth` one month and re-renders the grid; the oval label always reflects `visibleMonth`.
- Tapping the oval month/year label opens a new month/year picker popup (year list + 12-month grid, following the app's existing Teleport-to-body bottom-sheet pattern used by `CouponFormModal`/`ChannelManagerModal`/`CouponDetailModal`). Picking a month/year sets `visibleMonth` and closes the popup; the label and grid update to match.
- Replace the hardcoded `selected`/`today` day flags with real state: `today` is the device's actual current date (recomputed, not stored); `selectedDate` defaults to today and updates when the user taps/clicks any day cell (including a dimmed leading/trailing day from an adjacent month, which also navigates `visibleMonth` to that day's month). The selected-day style changes from the current sage-green border to a black (`--ck-ink`) border, per the updated reference.
- Wire the day indicators and the coupon list to real data: `CalendarPage` drops `mockPromoCodes` and loads channels (`useChannelsStore`) and all coupons (`listCoupons`) the same way Codes does. Replace the current small round dots with thin horizontal lines: a day gets one thin line, in that channel's color, per distinct channel that has at least one coupon whose `[startDate, endDate]` range includes that day, stacked with a small gap between them near the top of the day cell, in the same channel order used elsewhere in the app; a channel with no active coupon that day simply has no line (the remaining lines stack together, not leaving a gap in its place). The legend below the grid lists the user's actual channels (not a fixed site/etsy/instagram set).
- The list under the grid shows every coupon whose `[startDate, endDate]` range includes `selectedDate` (so it's empty when no coupon covers the selected day), heading labeled with the selected date, sorted by days-left descending by default (same underlying sort already implemented in `queries/coupons.ts`, so active/further-out coupons lead and expired ones fall to the end).
- The list reuses `CodeCard` exactly as Codes does for rendering, but without the `deletable` prop (no delete affordance on Calendar) and with `@select` wired to open the existing `CouponDetailModal` — matching how `CodesPage` already opens it, with delete's own `ConfirmDialog` flow not present here at all.
- **Follow-up, supersedes the line above:** a filter/sort toolbar — the same channel/status/discount-type filters and sort control Codes already offers — is added below the "Active on [date]" heading, scoped to the selected-day list only (the month grid's channel indicator lines and legend stay unfiltered, always showing the full picture). The toolbar markup is extracted from `CodesPage` into a new shared `CouponFilterToolbar` component so both screens render it identically; Codes' own behavior is unchanged, just relocated.
- **Follow-up visual refinements:** the gap between stacked channel indicator lines is increased; lines run the full width of the day cell with no horizontal inset, so same-colored lines in adjacent days visually fuse into one continuous bar (matching that `.cal-days` already has no gap between cells); the day number moves from vertically centered to anchored near the bottom of the cell; and today's fill color changes from near-black (`--ck-ink`) to the app's sage accent (`--ck-sage`), with the selected-day black ring no longer suppressed when today is also selected (both now render together, since sage isn't visually redundant with a black ring the way near-black was).
- **Second follow-up round of visual refinements:** day cells get square corners (`border-radius: 0`) instead of rounded; the selected-day ring's border is now always reserved (transparent when not selected) so selecting a day no longer visibly shifts the channel lines inside it (a real layout bug, not just polish); the selected ring's color lightens from `--ck-ink` to `--ck-muted`; today's fill lightens further, from a solid `--ck-sage` to `--ck-sage-dim` with `--ck-sage` text (the same pairing `CodeCard`'s "Active" badge uses); and channel indicator lines thicken from 2px to 3px.

## Capabilities

### New Capabilities
- `calendar-view`: a real, navigable month calendar over live coupon/channel data — month navigation (prev/next + a month/year picker), per-day channel marks, day selection (defaulting to today) driving a filtered, sorted coupon list, and reuse of the existing coupon card/detail popup with delete hidden.

### Modified Capabilities
(none — `coupon-channels` and `coupon-list-filtering` are consumed as-is via their existing queries/stores; no requirement in either spec changes)

## Impact

- `apps/mobile/src/views/CalendarPage.vue`: rewritten — real month-grid computation and navigation state, real day-selection state, `useChannelsStore`/`listCoupons` in place of `mockPromoCodes`, `CodeCard`/`CouponDetailModal` wiring.
- `apps/mobile/src/data/promoCode.ts`: `mockPromoCodes` becomes unused once `CalendarPage` no longer reads it (Codes already migrated off it); left in place or removed per design.md, but no shape change.
- New component: a month/year picker popup (Teleport-to-body bottom-sheet pattern), plus a small date-grid utility (month generation, leading/trailing days, per-day channel-overlap computation) — likely `apps/mobile/src/utils/calendar.ts`, reusing `PromoCode`'s `startDate`/`endDate` and the existing `channels` color data.
- `apps/mobile/src/i18n/locales/en.ts`: new strings for the month/year picker popup; existing `calendar.*` strings (title, weekdays, legend, activeOn) mostly carry over.
- `apps/mobile/src/theme/variables.css` / `CalendarPage.vue`'s `<style>`: selected-day border color changes from `--ck-sage` to `--ck-ink`; the `.marks`/`.m` dot styling is replaced with thin, edge-to-edge, stacked horizontal lines inset from the top of `.day`; today's fill moves from `--ck-ink` to `--ck-sage`; the day number anchors near the bottom of the cell.
- `apps/mobile/src/views/CodesPage.vue`: its inline channel-chip/sort/status/discount-type toolbar markup is extracted into a new `apps/mobile/src/components/CouponFilterToolbar.vue`, imported back in with no behavior change.
- `apps/mobile/src/db/queries/coupons.ts` / `utils/calendar.ts`: `CalendarPage` gains its own local filter/sort state for the selected-day list (separate from `useCouponsStore`, per design.md Decision 1) and a small in-memory sort helper for `daysLeft`/`expiringSoon` mirroring `sortRowsInMemory`'s logic over the `PromoCode` shape.
- No `db/schema.ts` or migration changes — this change only adds a new read pattern (all coupons/channels, unfiltered) on top of the existing `listCoupons`/`listChannels` queries.
